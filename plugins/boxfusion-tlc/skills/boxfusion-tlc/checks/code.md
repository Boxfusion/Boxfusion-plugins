# Code checks (Developer)

Report what causes or risks real problems, with the system's own code as the example — not a style-lint dump. For every finding, explain the principle in plain English, because the report teaches as well as diagnoses.

**This file obeys `references/operating-standard.md`.** Every check is a decision procedure: **INPUT (exact grep/decompile) → PREDICATE (boolean) → VERDICT → ANCHOR**, then **REMEDIATION (plan_id + template) → REGRESSION TEST → SEVERITY INPUTS**. A finding is raised **iff** the predicate is true and an anchor exists. IDs are `CODE-X@<anchor>` (operating-standard §3) — **never** `CODE-X-1/-2/-3`; multiplicity is carried by the anchor (N anchors ⇒ N findings that collapse by identical string). The anchor is a **symbol/role**, never a raw line number (a `Where:` prose field may carry `file:line`, but the `finding_id`/`anchor` may not). Severity is scored intrinsically from the operating-standard §5 table against the manifest's `severity_target` (evidence level is a separate axis, not a severity input) — a starter-default finding is **Low on a demo/near-empty copy, High for a real production target**, and that is the severity_target doing the work, not a per-run gut call.

**Honesty rule (operating-standard §9).** Two CODE checks cannot be made reproducible by a text grep — they need semantic/dataflow analysis (a Roslyn pass). They are marked **NON-DETERMINISTIC**, emit findings tagged `non_deterministic:true`, and the normalizer drops them from the acceptance diff until the analyzer lands: **CODE-J** (predicate/closure correctness) in full; the **dataflow sub-predicates of CODE-A** (null-dereference proof — *every* null-deref candidate, failure-returns-null-overwrites-data); the **semantic-duplication sub-predicate of CODE-D** (same rule, different implementations); and the **import-graph sub of CODE-G** (unreferenced-tree share %, dead-wired component reachability — `CODE-G@$FE#import-graph`). Everything else is a deterministic grep/decompile + bounded local read.

**Pins (from the manifest, operating-standard §1):** `$SHA` = `$(SheshaVersion)` from `backend/Directory.Build.props`; `$DLL` = the `Shesha.Application/$SHA` path resolved from `Web.Host/obj/project.assets.json` (every decompile targets this exact path). `$FE` = the front-end app root(s) (e.g. `adminportal/src`). A decompile/framework-timing dimension needs `ilspycmd`; absent ⇒ `NOT-ASSESSED(no-decompiler)` on that dimension only.

**Mandatory fixed NOT-ASSESSED / quarantine anchors (every operator emits every one, always — so two runs' non-scored sets match exactly):** `CODE-A@telemetry`, `CODE-A@probe`, `CODE-B@probe`, `CODE-C@probe`, `CODE-J@analyzer` (the Roslyn-replacement marker). These carry `severity:"Info"` and never enter the fix-order list (operating-standard §6 ranks only scored Critical/High/Medium/Low).

## Determinism pins (apply exactly)
- **Overlap priority (no double-emit across CODE checks).** The static-service-locator god-helper (static ctor resolving scoped deps via `IocManager.Instance.Resolve<>`, mutable static settings) is **one finding owned by CODE-B** (`RC-service-locator-di`); CODE-H references it but emits only the *aggregate* `CODE-H@sln:iocmanager-resolve-sites=<n>` count, never a second per-type record for the same symbol. A test/debug endpoint that is ALSO a security reach is **handed over to the security closed set** (below), not double-scored here.
- **Security handovers are owned by the security closed set, not re-scored here. In a CODE-division run (`--area code` or the code operator), `CODE-F-1`/`CODE-G-1` and every other security-owned record are NARRATED ONLY and MUST NOT appear in the code division's `findings.json`** — they are emitted solely by the security division's run, so a code operator that writes a `CODE-F-1`/`CODE-G-1` object diverges from one that (correctly) omits it. The CODE area *detects and narrates* (with the no-blame starter framing) but the **scored record lives in `findings.json` under the SEC check** with the SEC `plan_id` and the shared security `root_cause` (operating-standard §3):
  - client-trusted, URL-derived scope header (`sha-position-appointment-id`) → emitted as **CODE-F-1** (anchor `adminportal/src/middleware.ts#middleware`, `plan_id=PLAN-SEC-A`, `root_cause=RC-browser-trusted-flow`, auth_bypass × any_authenticated → Critical).
  - inverse / stubbed permission-checker (`{Project}PermissionChecker` keyed on `username=="admin"`, `default: return false`, `throw NotImplementedException` overloads) → emitted as **CODE-G-1** (anchor `...#HcmPermissionChecker.IsGrantedAsync`, `plan_id=PLAN-SEC-C`, `root_cause=RC-no-authz-model`, auth_bypass × any_authenticated → Critical).
  - anonymous/test-only integration endpoints reachable in prod → SEC-K/SEC-D closed set (`RC-starter-hardening`/`RC-browser-trusted-flow`).
  - committed starter secrets / CORS / Swagger / Playground / ELMAH / Hangfire / JWT-lifetime → SEC-E/SEC-O/SEC-D/SEC-I (`RC-committed-secrets`/`RC-starter-hardening`).
  These two handover tokens (`CODE-F-1`, `CODE-G-1`) are the **one** exception to the no-ordinal rule — they are grandfathered fixed tokens in the security closed set (security.md pins them so `--security-only` always raises them). Every other CODE finding is `CODE-X@<anchor>`.
- **`root_cause` is an enumerated `RC-code-*` id** (vocabulary below), never free text. `fix_order_rank` is a pure function of {severity, root_cause, anchor} (operating-standard §6), so it matches across runs. Handover findings carry their **security** root_cause.
- **Empty-verdict records are deterministic and fixed:** a check that finds nothing emits `CODE-X@none` with `evidence_level=CODE-ONLY, severity=Info` (e.g. `CODE-D@god-class=none`), so two runs' empty verdicts match.

## Exact greps (one command → one result; replace described predicates where given)
- **CODE-A empty catch** = `rg -nU "catch\s*(\([^)]*\))?\s*\{\s*\}" backend/src $FE --type-add 'code:*.{cs,ts,tsx,js}' -tcode` → one finding per match.
- **CODE-A log-only catch (EXACT — this is the deterministic log-only set; no other interpretation):** `rg -nU "catch\s*\([^)]*\)\s*\{\s*(_?[Ll]og(ger)?\.[A-Za-z]+\([^;{}]*\)\s*;\s*)+\}" backend/src --type cs` → the catch body is **one-or-more logger calls and nothing else** (no `throw`, no `return`, no other statement). One finding per match. Do **not** widen this to "a catch that logs somewhere in its body" — only a body that is *exclusively* logging qualifies; a catch that logs then rethrows or returns a safe prior value is not a finding. (This closed grep is what removes the A-flags-jobs / B-flags-helpers split: both operators run this exact command and get the identical set.)
- **CODE-A rewrap-without-inner** = `rg -n "throw new \w*Exception\([^)]*\.Message" backend/src --type cs`, PREDICATE = the caught `ex` is not passed as the `innerException` argument.
- **CODE-A null-deref candidate** = `rg -nU "(FirstOrDefault|SingleOrDefault|Find)\([^)]*\)\s*[\.\[]" backend/src --type cs` (immediate dereference of a possibly-null lookup) — **candidate only; ALWAYS emitted with `non_deterministic:true` (proving the miss is `[ND]`), so the normalizer drops every null-deref candidate from the acceptance diff.** Never emit a null-deref candidate as a plain CODE-ONLY finding — that is the error that let one operator carry a dozen job/helper anchors the other did not.
- **CODE-B static-capture (EXACT — capture-once only, not re-resolve; one finding per TYPE, anchor `#<Type>`):**
  1. **Candidate files** = `rg -lU "=\s*IocManager\.Instance\.Resolve" backend/src --type cs`. The regex `=\s*IocManager` matches an **assignment** `_field = IocManager.Instance.Resolve<…>()` and, because `=>` is `=` then `>`, it does **NOT** match an expression-bodied `=> IocManager.Instance.Resolve<…>()`. This is the whole distinction: assignment = capture-once (defect); `=>` = re-resolve-per-call (service-locator, CODE-H count only).
  2. **A type qualifies** iff, in a candidate file, a `static` field (`static readonly X _f;` or `static X _f`, in a `static class` or an instance class) is **assigned** from `IocManager.Instance.Resolve<…>()` — whether in a **field initializer** (`static X _f = IocManager…Resolve()`) **or a static constructor body** (`static Ctor(){ _f = IocManager…Resolve(); }`; the declaration line has no `=`, the assignment line has no `static` — you must read the static ctor, not just the field line). ∪ a non-`readonly`/non-`const` mutable `static` field holding request-scoped state.
  3. **EXCLUDE** a type whose IocManager use is **only** expression-bodied `=> Resolve()` (re-resolve per access) — that is CODE-H-only (`sln:iocmanager-resolve-sites`), never CODE-B. pd-Hcm `InputFileManager` (all `=>` members) is excluded; `PERSALHelper`, `SaGovLeaveCalculator`, `LeaveRequestExtension`, `LeaveRequestDatesCalculator` (static-ctor `_f = IocManager…Resolve()` into `static readonly` repo fields) all qualify.
  Emit one `CODE-B@<path>#<Type>` per qualifying type.
- **CODE-H service-locator count** = `rg -c "IocManager\.Instance\.Resolve" backend/src --type cs | awk -F: '{s+=$2} END{print s}'` → the solution anchor value.
- **CODE-B sync-over-async** = `rg -n "\.GetAwaiter\(\)\.GetResult\(\)|\.Result[;\)]|\.Wait\(\)|AllowSynchronousIO\s*=\s*true|\.List\(\)" backend/src --type cs` (NHibernate `.List()` is the sync enumeration; `.Result`/`.Wait()` block threads).
- **CODE-B DI-lifestyle** = `rg -nU "\.Register<[^>]+>\([^)]*Singleton|AddSingleton<" backend/src --type cs`, PREDICATE = the registered type depends on `IRepository`/`IUnitOfWork`/`IAbpSession`/`HttpContext`.
- **CODE-D magic-strings** = `rg -n "\"(One-Step Approver|PMDS[^\"]*|Approver|Recommender|[A-Z][a-z]+ Approver)\"" backend/src -g '!**/migrations/**' -g '!**/Migrations/**' --type cs` ∪ role/status/setting-name string literals compared with `==`; PREDICATE = the literal is a role/status/permission/setting name used in ≥2 **non-migration** files and not sourced from a constant/reference-list/`enum`. **FluentMigrator migration files (`**/migrations/M*.cs`) are EXCLUDED** — they legitimately carry one-off SQL/seed string literals that are not application magic-strings; a literal appearing only in migrations is never a CODE-D finding (this removes the operator split where one flagged `migrations/m*.cs#M*` and the other did not).
- **CODE-D god-class (EXACT public-METHOD count — excludes ctors/consts/properties):** count public **methods** only: `rg -nU "^\s*public\s+(static\s+|async\s+|virtual\s+|override\s+|sealed\s+)*[\w<>,.\[\]?]+\s+\w+\s*\(" <file>` then **subtract constructor lines** (a constructor's token before `(` equals the class name — it has no return type; exclude it). A `public const`/`public readonly`/property (no `(`) is not counted. Raise iff the resulting method count is **strictly > 20**. pd-Hcm `AppraisalRatingManager`: 20 public methods + 1 ctor — the raw `public …(` grep counts 21 (ctor included) but the pinned method count is **20, which is NOT > 20**, so `CODE-D@god-class=none`. Do not count the constructor.
- **CODE-E specifications absent** = `rg -n "ShaSpecification<|ISpecification<|\[GlobalSpecification" backend/src --type cs` → **no match ⇒ raise** `CODE-E@sln:specifications=0`.
- **CODE-E server-validators (EXACT `.Application`-project enumeration — both operators produce the identical set):**
  1. **Project list** = every directory matching `backend/src/[Mm]odule/*.Application/` (case-insensitive; the dirs under `Module/` are **project-level**, e.g. `SaGov.Leave.Application`, `Shesha.Qms.Application` — there is no intermediate module dir). Sort ascending. The `<module>` token in the anchor is that **project directory's leaf name lowercased verbatim**, including the `.application` suffix (e.g. `sagov.leave.application`, `shesha.qms.application`) — this is the deterministic form; do **not** strip `.application` to a module name.
  2. A project **needs** a validator iff it contains an app-service **class declaration**: `rg -l "class \w*AppService" <projdir> --type cs` is non-empty. (Never `rg -lw "AppService"` — `AppService` is always a suffix, so `-w` matches nothing.)
  3. A project **lacks** one iff `rg -l "AbstractValidator<" <projdir> --type cs` is empty. **Scope is that `.Application` project dir only** — a validator living in the sibling `.Domain` project does **not** count (Fluent validators for app-service inputs belong in `.Application`), which is why `shesha.qms.application` qualifies even though `shesha.qms.domain` has validators.
  4. Emit `CODE-E@<projdir-leaf-lowercased>:no-server-validators` for **every** `.Application` project where (2) AND (3), iterating the sorted list — no operator picks a subset. pd-Hcm: `sagov.leave.application`, `sagov.pmds.application`, `shesha.hcm.application`, `shesha.leave.application`, `shesha.pmds.application`, `shesha.qms.application` (6).
  If no `*.Application` project dirs exist (non-modular solution), emit the single `CODE-E@sln:no-server-validators` when the solution has mutating app-services but zero `AbstractValidator<`.
- **CODE-G unwired workflow task** = for each `: *\w*ServiceTask` / `IServiceTask` class, grep its class name across the Live workflow definition JSON (`*/ConfigMigrations/*`, `.shaconfig` contents) → **zero hits ⇒ raise** `CODE-G@<path>#<Type>` (unwired).
- **CODE-G starter landing page (EXACT, deterministic, always emitted or `@none`):** `rg -ln "Shesha Boilerplate|APP_NAME\s*=\s*['\"]Shesha" $FE` → if any hit, emit the single fixed anchor `CODE-G@$FE/app/page.tsx#Home` (resolve `$FE` to the actual front-end root, e.g. `adminportal/src`); no hit → `CODE-G@starter-landing=none`. Both operators run this and agree.
- **CODE-G unreferenced-tree share & dead-wired component [ND]:** "~N% of `$FE` is unreferenced" and "custom component X is dead-wired" require an **import-graph / reachability** analysis a grep cannot do reproducibly (the % and the reachable set vary with how imports are resolved). Emit these with **`non_deterministic:true`** (fixed marker `CODE-G@$FE#import-graph`, Info) so the normalizer drops them from the diff — **never** a bare `CODE-G@$FE/` percentage record or a per-component dead-wire record in the scored set. The deterministic replacement is an import-graph tool (`add-analyzers` / a bundler reachability report).
- **CODE-H raw-SQL config writes** = `rg -nU "Execute\.Sql" backend/src --type cs` ∩ bodies touching `Core_ShaRoles|Core_ShaRolePermissions|Frwk_PermissionedObjects` (0.43–0.44) or `frwk\.` (0.45); PREDICATE = the statement is an `INSERT`/`UPDATE`/`DELETE` of permissions/roles/forms/settings (a read-side `VIEW`/`JOIN` is **not** a finding — see pd-Hcm CODE-H-3, which was correctly cleared).
- **CODE-H name-without-version lookup (EXACT — includes config-repo `.Name ==` lookups):** `rg -nU "\.Name\s*==\s*\w+\.(TemplateName|Name)|\.Name\s*==\s*[\"']|FirstOrDefault(Async)?\([^)]*\.Name\s*==" backend/src --type cs`. PREDICATE = a **versioned configuration entity** is resolved by `Name` with **no** `IsLast`/`VersionStatus`/`Live` filter in the same query. A versioned config entity is any of: a `*Config`/`*Configuration` type (e.g. `NotificationTypeConfig`, `NotificationChannelConfig`, `FormConfiguration`, `SettingConfiguration`), a template lookup (`t.Name == layout.TemplateName`), a `ReferenceList`, or an `EntityConfig`. **Resolving a plain domain entity by name (Person, Cycle, a lookup with no versions) is NOT a finding.** Emit **one finding per enclosing method** `CODE-H@<path>#<Type>.<Member>` control=name-no-version (collapse multiple config lookups in one method to that one anchor). **The compared value may be a string literal OR a variable/parameter** — `x.Name == "performance-review-open"` and `x.Name == notificationTypeName` both qualify (both resolve a versioned config entity by name with no version filter); never restrict to literals. **The enclosing method may be public or private** — a private helper like `NotifyRevieweesForCycleCreationAsync<TEntity>` that performs the lookup is itself the anchor. pd-Hcm: the 4 PDF controllers (`t.Name == layout.TemplateName`) **and** every `*NotificationSender` method that does `_notificationTypeConfigRepo.FirstOrDefaultAsync(x => x.Name == "…")` / `_notificationChannelConfigRepo.FirstOrDefaultAsync(x => x.Name == "Email")` with no version filter — both config entities are versioned `ConfigurationItem`s, so a draft/retired version can be picked silently.

## CODE-A: Error handling. **impact_class=maintainability (save-path data-loss subs = data_integrity). RC-error-opacity.**
Swallowed failures make users see success when the work failed; log-only hides the failure but leaves a trace; a rewrap without the inner exception loses the cause; a lookup that can miss and is dereferenced is the source of "random" 500s; and the most dangerous shape is **a failure that returns null and a caller that overwrites existing data with it** (a sync/refresh that clears an attachment or field when the fetch fails — on failure, keep the old value).
- **INPUT:** the four exact greps above (empty catch, log-only, rewrap-without-inner, null-deref candidate). **Count log-only catches separately from empty catches** — both hide failures; log-only at least leaves a trace. If a framework base class rewraps without the inner exception, it is a **Shesha-team** item, not a developer finding.
- **PREDICATE (one finding per site):**
  - empty catch: the `catch` block body is empty → `CODE-A@<path>#<Type>.<Member>` control=empty-catch.
  - log-only catch: the body contains **only** logging (`_logger.*`/`Log*`/`console.*`) with no `throw`/`return` of a safe prior value → control=log-only-catch.
  - rewrap-without-inner: `throw new …Exception(…ex.Message…)` not passing `ex` → control=rewrap-without-inner.
- **VERDICT/ANCHOR:** `CODE-A@<path>#<Type>.<Member>` (+ control). A correctly-silent guard (a `SafeGetDate`-style parse, a `JobExecutionLock`, a `catch(Exception){throw;}` no-op) is **not** a finding — read the body before calling it a swallow (pd-Hcm cleared `PersalImportServiceBase.SafeGetDate`, `JobExecutionLock`; flagged the `ReleaseSaGovLeaveBalanceServiceTask` rewrap and the commented-out Persal audit logging).
- **[ND] dataflow subs (tag `non_deterministic:true`, excluded from the diff):** null-dereference **proof** (find the input that makes the lookup miss) and **failure-returns-null-overwrites-data** need dataflow analysis a grep cannot do reproducibly → needs a Roslyn nullable-flow analyzer. Emit the candidate anchor with `non_deterministic:true`.
- **EVIDENCE (pinned, per anchor — no operator discretion):** an empty catch, a log-only catch, or a rewrap-without-inner read from **live source** → **CODE-ONLY**, always. **VERIFIED-ARTEFACT is reserved for exactly two shapes:** (a) the swallow/loss sits in a **commented-out dead line** (a `//`-prefixed block), or (b) the rewrap is in a **decompiled framework base class** (`$DLL` via `ilspycmd`). Every other CODE-A site is CODE-ONLY. Live 500 reproduced needs backend → `CODE-A@probe` `NOT-ASSESSED(no-backend)`; "does it fire in prod" needs telemetry → `CODE-A@telemetry` `NOT-ASSESSED(no-telemetry)`.
- **REMEDIATION `PLAN-CODE-A`:** replace empty/log-only catches with a specific catch that rethrows a `UserFriendlyException`/domain exception or lets it propagate; preserve the inner (`throw new X("…", ex)`); guard nullable lookups (`?? throw`/early-return) and **never overwrite a good value with a failed fetch's null**; restore or remove commented-out audit logging; framework-base rewraps → Shesha-team report.
- **REGRESSION TEST:** `ErrorHandling_NoSwallowedOrDataLossOnFailure_Test` + the `EmptyCatchAnalyzer` Roslyn rule as the standing guard; for a data-loss fix, a unit test where the fetch throws and the prior value is asserted intact.
- **SEVERITY:** maintainability × local_only → **Low**; the save-path data-loss sub data_integrity × any_authenticated +pii_basic → **High** (tagged `non_deterministic:true`).

## CODE-J: Query & predicate correctness (static). **NON-DETERMINISTIC (quarantined). impact_class=data_integrity. RC-predicate-correctness.**

- **Detect (candidate greps only):** lambda parameter shadows an outer variable (`.Where(x => x.Child.Id == x.Id)` where the lambda `x` hides an outer `x` — an always-false join, seen as `GetEquipmentBooker`); constant predicates (`x.A == x.A` always true; `x.Id == x.OtherId` that can never hold); wrong join key / wrong navigation (filtering a child by its own id instead of the parent id; a `FirstOrDefault` whose column set cannot match); a projection that drops the filter (`.Select(...).Where(...)` ordering that filters after a client-side materialise — overlaps ORM-D but yields wrong, not just slow, results).

- **REMEDIATION `PLAN-CODE-J`:** fix the predicate; name the lambda parameter distinctly; add the unit test (two rows where the correct predicate selects one — the current code selects none or all, failing today for the right reason, no backend needed). **The deterministic detection vehicle is a Roslyn analyzer** — recommend `add-analyzers` (a shadowing / constant-predicate analyzer) as the standing guard rather than claiming the code is clean.
